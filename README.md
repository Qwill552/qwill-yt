# Qwill YT — очередь просмотра YouTube

Личный сайт-очередь для видео с YouTube: вставляешь ссылку — появляется карточка
с названием, каналом, длительностью и датой публикации, отсортированная по
приоритету (Важно / Средне / Позже). Развёрнут на `qwill-yt.mooo.com`.

Так же принимаются ссылки на аниме с `animego.me`: карточка собирается с
постером (он крупнее превью YouTube, поэтому показывается в вертикальном
формате 5:7), названием, студией-аниматором вместо канала, количеством серий
вместо длительности и датой выхода. Такие карточки всегда попадают в
раздел «Аниме».

Счётчик серий на аниме-карточке показывает «просмотрено / доступно»
(`0/12 эп.`): вторым числом всегда идёт количество уже вышедших серий — для
онгоингов берётся именно оно, а не запланированное общее число со знаком `?`.
Клик по счётчику превращает его в поле ввода: вписал цифру — сохранилось.

Собран на TanStack Start (React 19 + Nitro), очередь хранится в `localStorage`
браузера. Для продакшена Nitro собирается с пресетом `node-server` и
запускается как systemd-сервис на порту 4100 за Caddy-реверс-прокси.

## Приём ссылок извне: `/api/queue-ingest`

Поскольку очередь живёт в `localStorage`, а не в базе, для добавления видео
из внешних источников (например, прямо с YouTube) есть небольшой
«почтовый ящик» на сервере:

- `POST /api/queue-ingest` — принимает `{ url, priority }`, требует заголовок
  `Authorization: Bearer <INGEST_TOKEN>`, резолвит метаданные видео и кладёт
  запись в очередь на диске (`data/pending-queue.json`, не версionируется).
  Второй вариант тела — уже готовая карточка аниме:
  `{ source: "animego", url, priority, title, studio, thumbnail, episodes,
  publishedAt }`. Он нужен потому, что часть тайтлов AnimeGO не отдаёт
  анонимным запросам: в браузере с залогиненной сессией страница
  открывается, а серверу прилетает 404. В этом случае страницу читает
  юзерскрипт прямо в браузере и присылает данные сюда.
- `GET /api/queue-ingest` — сайт сам дёргает этот эндпоинт при каждом
  открытии, забирает накопленные ссылки, добавляет их в очередь и очищает
  ящик.

`INGEST_TOKEN` задаётся переменной окружения на сервере (в systemd-юните),
в репозитории не хранится.

## Tampermonkey-скрипт: `qwill-yt.user.js`

Скрипт добавляет на YouTube два способа закинуть видео в очередь, не заходя
на сайт:

1. **Кнопка на странице просмотра.** Слева от кнопки лайка появляется
   круглая кнопка со значком ссылки, оформленная в нейтральных тонах самого
   YouTube (подстраивается под светлую/тёмную тему). Клик — кнопка плавно
   растягивается в кластер из трёх сегментов с разделителями: огонёк
   (Важно), жёлтый кружок (Средне), серый кружок (Позже). Клик по сегменту —
   кнопка сужается обратно, на пару секунд показывается галочка об успехе
   (или предупреждающий значок, если запрос не прошёл).
2. **Контекстное меню в любой ленте.** Правый клик по карточке видео —
   на главной, в поиске, в блоке «Далее»/рекомендациях, в плейлистах —
   открывает вместо системного меню Chrome вертикальное меню с теми же
   тремя пунктами (Важно / Средне / Позже) для видео под курсором, включая
   момент, когда на карточке уже проигрывается автопревью.

Оба способа шлют ссылку на видео на `qwill-yt.mooo.com/api/queue-ingest`
через `GM_xmlhttpRequest` (в обход CORS), сайт подхватывает её при следующем
открытии.

На `animego.me` (и зеркалах `.org` / `.one` / `.club`) скрипт добавляет на
страницу тайтла карточку «Очередь Qwill» в вёрстке самого сайта — в правой
колонке на широких экранах и над заголовком на узких. Кнопка «В очередь»
раскрывается в три варианта приоритета, дальше показывается статус отправки.
В отличие от вставки ссылки на сайте, здесь данные читаются из DOM уже
открытой страницы, поэтому работают и тайтлы, скрытые от неавторизованных.

### Установка

1. Установите расширение [Tampermonkey](https://www.tampermonkey.net/).
2. Откройте `qwill-yt.user.js`, скопируйте содержимое в новый скрипт
   Tampermonkey (Dashboard → «+»).
3. Замените `__INGEST_TOKEN__` на значение `INGEST_TOKEN`, которое задано в
   systemd-юните сайта на сервере.
4. Сохраните — готово, ничего больше настраивать не нужно.

Скрипт уже установлен и обновился в репозитории? Тогда откройте его в
Tampermonkey, замените содержимое на новое и снова подставьте
`INGEST_TOKEN` вместо `__INGEST_TOKEN__` — токен в репозитории не хранится,
поэтому при каждом обновлении его нужно вписать заново.
